La aplicación y los repositorios de Trips, Reservations, Groups, Mobility,
Expenses y Safety tienen dependencias de lectura explícitas, sin ciclo nuevo
de módulos Nest. Los repositorios reúnen operaciones Prisma en unidades de
trabajo. Hay acoplamiento a los tipos de lectura de Trips y a los repositorios
de Reservations. El reemplazo de ese acoplamiento se reserva para una necesidad
funcional demostrada. Los contratos de salida se proyectan antes de llegar a Expo.
El backend conserva rate limiting global y por operación, validación de entradas
con propiedades extra rechazadas, CORS por origen y cabecera para mutaciones.
La API protege acceso directo a recursos ajenos y emisión/canje de QR con
sesión y pertenencia. Cookies web HttpOnly y SecureStore nativo conservan el
ciclo de sesión existente. El filtro HTTP evita registrar el cuerpo, códigos,
contraseñas y tokens. La prueba física de SecureStore queda abierta.

por el árbol. Las versiones declaradas de Expo SDK 54, React, Nest y Prisma
permanecen. Se requirió una resolución dirigida de npm después del primer
intento de instalar overrides sobre el lockfile previo.

El [informe anterior](PRODUCT_CONSOLIDATION_DEPENDENCIES.md) conserva el análisis
de las alertas moderadas y la compatibilidad de cámara, ubicación y QR.

La auditoría final detectó 38 entradas en total y 16 con `--omit=dev`.
Ambas incluyeron cuatro altas y cero críticas. Las cuatro altas corresponden
a `image-size` y la cadena `decode-uri-component` → `query-string` → Expo Router.
El corte inicial tenía 42 y 20, respectivamente, con ocho altas. Uno de los
riesgos residuales afecta el proceso de empaquetado y el otro la cadena de
navegación. El análisis mantiene abiertos ambos hasta una actualización
compatible y verificada.

En regresión, la restricción SQL de tipos de aviso y la de resolución de
propuestas revelaron incompatibilidades con los estados nuevos. Se ampliaron
con las migraciones `20261126131000_trip_notification_lifecycle` y
`20261126132000_pickup_proposal_expiration`. Se replicó el caso de confirmación
con avisos en `release-economics-safety` y se amplió la prueba de propuesta
para comprobar que PostgreSQL conserva la expiración.
